## 零、总策略

**评审看过的方案里，绝大多数是「我们做了个 AI 助手 + 一张架构图 + 美好愿景」。**

真正稀缺的是**可信度**：真实的实测数字、可复现的验证方式、以及"我怎么知道它行"的证据链。

所以核心策略是一句话：

> **不要写"我做了什么"，要写"我怎么知道它行"。**

技术再强，如果读起来像套壳，评价就上不去；反过来，功能清单短一点，但每一句都有数据和证据兜底，可信度完全不同。

### 第 3 章的三条差异化怎么讲

1. **不选场景** —— 没有"请选择：1 会议 2 课程 3 视频 4 对话"。场景自动判断，产出跟着变（会议纪要 / 课堂笔记 / 内容笔记 / 对话记录）
2. **数据不出本机** —— 本地 Whisper + 本地混元，拔网线也能用。这是调研里排序最高的卖点
3. **结束就有交付物** —— 不是一个"翻译工具"，是一份能直接验收的纪要：md + html + csv + srt

### 第 4 章选哪三个技术点

从 `PROJECT.md` §3.5 里挑，标准是"**能说明我们真的调过**"，而不是"听起来高级"：

| 推荐 | 讲什么 | 为什么选它 |
|---|---|---|
| **① 语言锁定** | 逐块检测在 3 秒碎片上只有 p≈0.22 把握，判错一次整段就废；所以语言是**会话级属性**而不是句子级 | 体现对模型行为的真实理解 |
| **② 幻觉过滤五道闸** | no_speech / 置信度 / 黑名单 / 提示词回显 / 跨段重复。其中"提示词回显"是实测发现：把术语表塞进 `initial_prompt` 后，模型在音频不清晰时会把词表**原样吐出来**，置信度还高达 0.99 | 这是别人踩不到、也想不到的坑 |
| **③ 段间重叠的 0.7 秒** | 1.5s → 整句被两段各识别一次；0.3s → 词被切在边界两侧；0.7s 才对。数字不是拍的，是试出来的 | 一个具体数字证明工程深度 |

## 二、第 5 章「实测与验证」详细展开 ⭐

这一章写四样东西。

### 5.1 性能数字（全部实测，不要估）

| 指标 | 数字 | 出处 |
|---|---|---|
| Whisper 识别 | 391–854 ms | §2.5 |
| 本地翻译 | 均 ~124 ms（77–320 ms） | §2.5 |
| **端到端（说完到出中文字幕）** | **~0.8 s** | §2.5 |
| 启动预热（Whisper 加载） | **6.9–8.4 s** | §2.5 |
| 识别置信度 | 0.75–0.90 | §2.5 |
| 显存占用 | Whisper 3.1 GB + 混元 0.7 GB ≈ 4.8 GB / 7 GB | §2.5 |

> **主动写"启动预热 7 秒"是有意的** —— 它说明"打开就听"在加载完成前不成立。
> 敢把不利数字写出来，其他数字才可信。

### 5.2 可复现的验证入口（这一条最硬）

> **"我们的每一项能力都有一条命令能验证，评审可以当场自己跑。"**

```powershell
.\Translator.exe --selftest --db t.db    # 13 组 47 例，秒级，不需要模型
.\Translator.exe --wav demo.wav --summarizer rules --db t.db --out o   # 20 秒跑完全链路
```

- `--selftest`：清洗、去重、术语纠错、提示回显、跨段重复、行动项校验、WAV 解析、后端选择规则 —— **全部不需要加载模型**
- `--wav`：11 秒音频 → 识别 → 翻译 → 落库 → 四类交付物，**零交互、退出码 0**

### 5.3 一个「发现缺陷 → 定位 → 修复 → 回归」的完整案例

**推荐讲这个（最有代表性、证据最全）：**

> 纪要的"作业与任务"里凭空多出一条不存在的作业，截止日期还写着 `today`。

完整证据链：

| 环节 | 内容 |
|---|---|
| 真实产物 | 会话 #11 的 `actions.csv` 里那条记录（截图） |
| 根因 | 抽取用的**触发表**里有「应该」，一句过场语也能命中；而 prompt 里那句"别乱抽"是祈祷不是保证 |
| 修法 | **触发表与判定表分开**：抽取宁宽勿漏，判定宁严勿滥；再加一个**纯函数校验器**跑在所有后端汇合点 |
| 回归用例 | 把那条真实字符串做成自检用例，永久守着 |
| 修后产物 | 5 条真待办全保留，假条目消失 |

**这一章要传达的不是"我们没有 bug"，而是"我们有一套能发现 bug 的机制"。**

同类备用素材（都很完整）：

- 云端模型把 `next Friday` 翻成「下周五」，我的日期依据规则**误杀**了正确日期 → 归一化后修复，3 条用例全部取自真实运行
- `--wav` 做完当天就抓到"静音上幻觉出 `Thank you.`" —— 而这类问题靠人耳听真实会议**极难发现**（谁会注意到纪要里多了句"谢谢"？）

> **一次真实运行的信息量，大于十次自检。** 这句话本身就是很好的论点。

### 5.4 A/B 对照能力

同一段音频**开/关各跑一遍**比对译名一致性 —— 这是"越用越准"能被证明的前提。

没有 `--wav` 就只能靠人耳听，改动无从对比。这也是为什么先做了这个工具。

## 三、PPT 大纲

### 3.0 先分清两种 PPT（**用途不同，写法完全不同**）

| | **A. 提交评分稿**（本次要交的） | B. 现场讲稿 |
|---|---|---|
| 谁解释 | **没人**。每页必须自己把话说完 | 你 |
| 怎么被消费 | **快速滑动**，可能只细看前两页 | 跟着你的节奏 |
| 页面标题 | **必须是结论句** | 可以是主题词 |
| 留白 | **不要**，信息密度要够 | 要，配合讲述 |
| 视频 | 单独上传附件，页面用**分镜截图带**占位 | 现场播放 |
| 评判标准 | 3 分钟内能不能记住 3 件事 | 讲得清不清楚 |

> **最要紧的一条**：提交稿里**每一页的标题就是一个结论**。
> 评审滑动时只读标题 —— **标题就是你的方案**，正文是给愿意停下来的人看的证据。

### 3.1 提交评分稿（10 页，结论式标题）

| 页 | 结论式标题 | 正文放什么 |
|---|---|---|
| 1 | **打开就听，结束就给总结** | 一句话 + 一张**实拍图**：字幕窗压在英文视频上（视觉锚，第一眼就懂） |
| 2 | 一个外贸业务员，两小时英文会议，记不下三个要点 | 具体场景 + 现有工具的不足。**不要讲行业趋势** |
| 3 | **双击 → 出纪要，全程零输入** | **分镜截图带**（见 §3.3），替代无法内嵌的视频 |
| 4 | 不选场景 · 数据不出本机 · 结束就有可验收的交付物 | 三条差异化，每条配一个证据 |
| 5 | 语言只检测一次，因为逐句检测准确率只有 **22%** | 技术点 ①：语言是会话级属性 |
| 6 | 段间重叠取 **0.7 秒**：1.5s 会重复整句，0.3s 会切断词 | 技术点 ②：数字是试出来的 |
| 7 | **说完到出中文字幕 0.8 秒；代价是启动要等 7 秒** | 实测数据表（含不利数字）+ 每页底部标注测环境 |
| 8 | **我们没装五道闸，是把五道闸拆成了可单测的函数** | 证据链 + 验证体系（自检 51 例 / 一条命令跑端到端 / A/B 对照） |
| 9 | 总结不该是终点：**问一次，下次就译得更准** | 知识闭环 + 三条腿已全通（附 A/B 实测） |
| 10 | 我们**不做** Linux 桌面版，因为字幕置顶在 Wayland 上做不到 | 诚实的局限 + 路线 + **可复现命令**（评审能自己跑） |

**第 5、6 页刻意拆成两页**：提交稿里"一页一个点"比"一页三个点"更容易被记住。

**每页底部放一行小字证据来源**，例如「实测：RTX 4060 Laptop，会话 #11」——可信度立刻不一样。

### 3.2 结论式标题改写示例（**最可操作的一条**）

| ❌ 主题式（现场可以，提交不行） | ✅ 结论式 |
|---|---|
| 技术架构 | 从系统声音到纪要，五步一条直路，**没有任何一步需要用户选择** |
| 性能测试 | 说完到出中文字幕 **0.8 秒**；代价是启动要等 **7 秒** |
| 幻觉过滤机制 | 我们装了五道闸，因为 Whisper 会把**你给的词表原样吐出来**，置信度还 0.99 |
| 知识库设计 | 总结不该是终点：**问一次，下次就译得更准** |
| 局限与展望 | 我们**不做** Linux 桌面版，因为字幕置顶在 Wayland 上做不到 |

### 3.3 视频那一页怎么处理

**不要放"视频见附件"这种占位页** —— 评审不会去找。改成 **分镜截图带**：

```
[双击图标] → [字幕窗滚动] → [按 Ctrl+Alt+Q] → [自动弹出纪要] → [actions.csv] → [transcript.srt]
   0:00          0:10            0:40              0:45            1:20           1:30
```

一页 6 格截图 + 时间轴，**不看视频也能懂流程**。

**PPT 和视频不重复**：

- **PPT = 论点 + 证据**（可读、可查、可复现）
- **视频 = 体验证明**（全程不剪辑、不输入，让评审相信这不是拼的）

### 3.4 提交稿特有的四个注意

1. **首页就给结论**。评审可能只细看前两页，封面不能只有标题和 logo
2. **数据要放大、对比要强**。快速滑动时 `0.8 秒` 要一眼看到，不能藏在表格里
3. **加一页"我们怎么知道它行"**（第 8 页）—— 自检 51 例 + 一条命令跑端到端 + A/B 对照，通常直接对应评分里的"技术可行性/完成度"
4. **如果比赛有官方模板或公开评分标准，优先对齐它**，而不是这份通用建议。公开了评分维度就主动在页标题里回应（如"创新性/可行性/完成度"）；没公开就别硬凑，会显得刻意

## 四、演示视频脚本（第 3 页，90 秒，**全程不剪辑、不输入**）

```
0:00  双击打开 → 直接开始（无任何交互、不按回车、不选后端）
0:05  播放一段英文演讲/课程视频
0:10  字幕窗出现：上一句中文 / 当前英文 / 当前中文，逐句往上滚
0:40  按 Ctrl+Alt+Q（镜头给到键盘，强调"一个动作结束"）
0:45  自动弹出浏览器：课堂笔记 / 会议纪要，带行动项表格
1:20  切到 transcript.srt 和 actions.csv —— "四类可直接验收的交付物"
1:30  完
```

**两个关键细节：**

1. **第 0:05 处不要解释"它在听系统声音"** —— 直接让它出字幕，冲击力更强。解释挪到第 4 页
2. **第 0:00 处不要出现任何命令行窗口** —— 双击图标就开始。如果还有黑窗口，先做 `PROJECT.md` §7 第 4 阶段的 GUI 壳

## 五、演示备份：`--wav` 防翻车 ⚠️

现场噪音、没网、声卡异常、Whisper 抖动都会让演示失败。**`--wav` 就是为此准备的：**

```powershell
.\Translator.exe --wav demo.wav --summarizer rules --db t.db --out o
```

它走的是**和真实采集完全相同的主循环**，所以显示效果一模一样，但**完全可复现、零交互、20 秒出结果**。

**建议做法：**

1. 提前用真实英文语音录一段 3–5 分钟的 `demo.wav` 放现场
2. 现场先试真实播放
3. **一旦有异常，立刻切 `--wav`，观众看不出来**

这是本项目**独有**的风险对冲能力 —— 别的团队没有可复现的输入源。

## 六、三件不要做的事

| 不要 | 原因 |
|---|---|
| **不要放"用了 XX 亿参数模型"** | 评审关心端到端体验，不关心参数量 |
